# surveyor: lessons across runs

One line per lesson, appended at the end; task state goes in the report
(`.claude/rules/subagents.md`, "Memory"). Committed with the tree.
- The host test double (`sys/arch/host`) refuses pageable `km_alloc`; host tests of a module with a kernel-memory buffer build it by hand with heap buffers, so count them as tied to the module's internals (section F), not as coverage of the allocation path.
- `docs/ZERO_UNSAFE.md` section 6 quoted `mod` line numbers, caller counts and a smoke list that had drifted by the next week; always re-measure what a planning document states and report the difference in section G.
- A smoke `--send` line with `||` is not a pipeline; grep for `|` not followed by `|` when counting the smokes that exercise pipes.
- `grep -lw <field>` counts names, not users: same-named fields of other structs (`KinfoFile.f_data`) and comments inflate it; count `\.<field>\.(get|set)\(` plus the typed accessors' callers, and report both numbers.
- A `diff-openbsd` step line need not name what it tests: `difftest syscalls ipc` (tools/difftest/difftest.c `t_ipc`) checks pipes, sockets and kqueue; read the probe source before saying a scenario is missing.
- The planning text a prompt quotes (docs/ZERO_UNSAFE.md sections, decisions) may exist only uncommitted in the working tree; check `git show <commit>:docs/...` and say which state each quoted number comes from.
- Whether a smoke exercises a kqueue filter depends on the userland program polling that object: grep `reference/openbsd-src/{lib,usr.bin,sbin,libexec}` for `poll(`/`kevent(`/libevent before claiming coverage (libfuse, libpcap and ksh do not poll).
- `unsafe-report` attributes by path prefix: its `arch/amd64` and `arch/arm64` rows include the boot loaders under `sys/arch/*/stand/` (302 `unsafe` at 9dbcbafa); split per file with `--json` before quoting a hardware total. In zsh loops never name a variable `path` (it is tied to PATH).
- Items a prompt names may not exist at the pin (N3.2: `uvm_anfree_list`, `uvm_km_kmemalloc_pla`); grep the C and LZ before counting, and check per-arch `#define`s (`__HAVE_PMAP_DIRECT` is amd64-only in OpenBSD, LZ sets it on arm64 too) before trusting a "both machines" deviation.
- Nested `use crate::uvm::{uvm_km::{..}}` defeats a `uvm::uvm_km` path grep; count files naming the module word in non-comment lines, then drop `mod.rs` and string-only hits (`db_stub!`).
- LZ ported only the attachments GENERIC configures on amd64/arm64 (no PCMCIA/CardBus/EISA/ISAPnP code at all); the set of ported devices is the `_CD` statics named in `sys/arch/*/conf/ioconf.rs`, so a "not in GENERIC" condition finds almost nothing (legacy-hw survey, 2026-10-17: 0 of 412 files).
- justfile variables are referenced bare inside other variables (`disk_login + "..."`, `replace(mouse_check, ...)`), not only as `{{var}}`; expand both before saying a smoke does not name a device, and a `<dev>\d+` regex misses `rd0a` and false-matches `fd00:` (IPv6).
- Line numbers taken from a `sed -n '/<CODE>/,..p'` print or a filtered `grep -v` view are not file lines; cite only `grep -n` output, and re-grep every cited line before handing back (N3.3 had ~60 to fix). In zsh a file list in `$VAR` needs `${=VAR}` to split.
- Read the C and `sys/hal/` before the caller greps: a permission denial mid-run (N4.1, 2026-10-18, a `sed` of reference/ chained with a `grep` of sys/) ends the survey, and what was not read yet becomes `## Incomplete`; keep each read a single simple command.
- Planning text names shapes and bridges that never landed (N4.2: ROADMAP's `Proc`/`Fd`/`Kq` bridges, decision 14's `CredRef` `[[seam]]`): check `bridges.toml`/`lineage.toml` rows, then `git grep <name> <branch>` over the unmerged `worktree-agent-*` branches, and say where (if anywhere) it exists.
- Two same-named runtime types coexist (`sys/sys/refcnt.rs` vs `hal::refcnt::Refcnt`, bsd `Mutex` vs `hal::Mutexed`): name the one a struct embeds, and count users of the hal one separately (hal `Refcnt` had 0 at e3cdf1d3).
