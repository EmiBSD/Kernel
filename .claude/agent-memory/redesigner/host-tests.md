name: redesigner-host-tests
description: Host tests and doubles: kernel::testutil, setup_real_memory, flakes, parallel tests

  type: feedback
---

- Dropping `Copy` breaks `Cell::get` and `StaticCell::read` at call sites: use `take`/`clone`/`set` on the Cell, `get().clone()` on the StaticCell. A stable "not Copy" check: `crate::crypto::testutil::assert_not_copy!` (E0283).
- MP host tests share CPU 0's per-CPU page magazines across setup_real_memory (uvm_page_test_reset resets them; a new per-CPU cache of kernel memory needs the same), and frees land there: count `uvmexp.free + percpucaches`; kernel tests over the real page system hold `testutil::MEMORY`.
- `amap_lookup` panics on an entry without an amap: unwire/wire paths test `aref.amap().is_some()` first (shared file and aobj mappings have none).
- `uvm_swapisfull()` is true with no swap (0 >= 0): out-of-RAM faults return ENOMEM, not ERESTART; a retry test raises `UVMEXP.swpages`. `uvmfault_anonget` counts rusage on every retry (the C's `goto retry`).
- Test helpers calling `init_shared()` (any `TypedPool::init`) from parallel tests race (EBUSY, then no pool, ~1 in 20): wrap the init in a `std::sync::Once`.
- `try_read` by the holder of the write witness panics "enter read deadlock" (the C's check): test "held elsewhere" from another thread (`thread::scope`).
- Shared kernel test maps go below the host's VM_MIN_KERNEL_ADDRESS: the map tests store UVM_MAXKADDR downwards, which desyncs a best-fit map above it ("uaddr_bestfit_remove: entry was not in tree").
- Baseline a filtered test run at another commit: stash the paths with a unique message, check out the base, run, come back, apply the stash by its SHA, then drop the `stash@{n}` whose SHA it is.
- An aborting test module hides its later failures: after fixing an abort, rerun the module at the fixing commit and bisect what fails behind it (wg's data-message tests were masked from 7311cd9d to 7227d7f8).
- A host test that drops an element linked on two pinned lists aborts the whole test binary (the second PinEntry panics during the unwind): link it on one list only in a should_panic test.
- bsd's MpLock depth is per `cpu_number()`, 0 for every host test thread: kern_lock.rs's release checks read a test-only per-thread depth that a test arms (`kernel_lock_checks_arm`), none elsewhere; never call `__mp_release_all` unarmed in a test (it zeroes CPU 0's depth every thread shares); host tests that reach `[K]` readers take `kernel_lock()` as the syscall would.
- A kernel test that writes the user-copy double's memory (64 KiB, shared by parallel tests) takes a range of its own; kernel::pipe's tests use USER_BASE + 64.
- A witness-taking form called from legacy code (VN_KNOTE's knote_locked) panics in the file systems' host tests, which run VOPs without the kernel lock: the legacy form takes the lock recursively itself.
- bsd tests that pass host pointers as user addresses (LZ's machine copyin double read host memory) fail with EFAULT once the path goes through `hal::user::UserPtr` (kernel::testutil's 64 KiB double): put the buffers at `USER_BASE + <own range>` with `copyout_slice`/`copyin_slice`; the double's copyinstr/copyoutstr copy strings since N4.6a.
- Kernel tests that need real sleeps reuse kernel::sched's harness (`pub(crate) mod tests`: SchedGlue, setup, thread, run_as, VCPUS, TABLES): one host thread sleeps on vCPU a, a spawned one acts on vCPU b after polling `stat()==SSLEEP && !P_INSCHED`; never write a second harness (one `register_start` per process).
- `pin!(..)` inside a call argument is not lifetime-extended (E0716): `let f = pin!(x); let f = use_it(f.into_ref());`.
- kernel::testutil's copyin32 double (a std Mutex over the user memory) is ~9 ns dev vs bsd host's 0.5 ns: bench it as a prim before blaming a futex-like design.
- kernel::testutil's 64 KiB user-memory double is shared: uio/select use 0x8000..0xC000, kernel::log 0xE000..0x10000 (kern.msgbuf's copy runs to the end and faults); pick an unused range and grep `USER_BASE + ` first.
- `klist_invalidate` waits for a knote's KN_PROCESSING to clear; kernel::event's `test_knote` stays processing, so a test of an object whose teardown invalidates its klists (ttyfree) must not attach test knotes or it hangs the run.
- kernel::tty's defaults leave VSTATUS disabled (CSTATUS 0o377, ttydefaults.h): a ^T test sets c_cc[VSTATUS] first; and `tputchar` emits "\r\r\n" for '\n' (the C's), which assertions must expect.
- Signals in a kernel test need the thread in `ps_threads`, `siginit` and `test_sigacts` (kernel::tty's `world()`), or pgsignal finds no one to deliver to.
- A kernel test whose path reaches `klock::reader()`/`witness()` (wait4, acct's session) panics "the kernel lock is not held": take `hal::klock::kernel_lock()` once per test thread in the setup (the double counts it), as a system call would.
- `kernel::test_proc_glue!(Name, Files, { fn hook(..) {..} })` overrides glue members (N4.6a); a second glue in one test module needs its own `mod` (the link types are module items), and a test process put in a pgrp/session is leaked with `mem::forget` (dropping it linked panics).
- `test_proc_glue!`'s tables are per test thread (a thread_local `ProcTables`): a list walk (`sysctl_doproc`) sees only the processes its own thread made, so an error that needs a process looked at (an unknown op's EINVAL) needs one put on the list first.
- hal's host user-copy double keeps its own addresses below 4 GiB (EFAULT outside the user and foreign runs) and copies raw above, so bsd's UIO_SYSSPACE host tests reach the kcopy token with real host pointers.
- A hal function the kernel calls with its test glues' thread types must not call `hal::thread::check_type` (one type per process): `slot_of` alone checks the layout (the TCB accessors).
- A kernel syscall that reads a global the tests must vary (kern.securelevel) takes it through a private `*_secure(.., &AtomicI32)` helper the public wrapper calls with the global, loaded at the C's read point: the test passes its own atomic and never races the sysctl tests.
- A double that answered a process-wide flag hid tests that set the real one: with SysInfo gone, kernel::reboot's should_panic test left REBOOTING set and the vnode error-path tests slept for ever ("uvndead"); give the setter a flag parameter (`reboot_flagging`).
- `event::tests::thread_of`'s Plimit has every limit 0 but NOFILE: a vm test over a real thread takes `vm::map::tests::thread(pid)` (lim_startup's limits), or mmap/protect answer ENOMEM.
- With the Uptime double gone, kernel tests read `kernel::tc` on the dummy counter: realtime near the epoch (unless time.rs's tests set it), coarse clocks frozen until `tc::tc_ticktock`; a 'time already past' is 0, a ratecheck test winds once first.
- Changing a FileGlue Data enum's variant moves bsd's pinned pool size test (`proc_glue::tests::the_pool_items_are_the_measured_sizes`, filepl 184 -> 176 at N5.0): run `cargo test -p bsd` after any BsdFileData change and note the size in the commit.
- physio and other user-memory paths test on the host over a real user map: `vm::map::tests::{setup, thread, user_vmspace}` + `uvm_mapanon` + `p.set_vmspace(Some(vm))`; with PMAP_NOMMU and NO_CONSTRAINT there is no bounce and PhysWindow is the user address itself (never dereference it in the test's strategy).
- bufpl (`BoxPool`) is shared by tests that hold MEMORY and tests that do not (fs::buf's): never assert its `nout()` across a test; the private OwnedList's `take` (I4) is the proof a buffer went back.
- A pool several tests initialise (`BoxPool::init` is EBUSY the second time): make every init tolerant (`let _ = POOL.init(..)`, or test `item_size()` first) in the tests and in the subsystem's own init (N5.1: bufinit vs fs::buf's tests raced).
- Function parameters drop in reverse order on unwind: `fn f(g: Guard, t: Token)` drops `t` first, and a token whose Drop takes the same lock panics 'locking against myself' recursively (stack overflow, a 1.4 GB test log). Put the guard parameter last; cap host test logs (`cargo test .. | head -c 2000000`, scratch tcap.sh).
- A guard made as a temporary inside a call's arguments lives to the end of the statement: `lend(BufRef::acquire(&mut CACHE.lock(), r))` holds CACHE while lend parks (and takes it again): bind the inner result first; and test every boundary helper by calling it (with_private_buf had no test and deadlocked every softraid I/O, N5.1).
- To prove a walk's lifetime bug, make the release that frees memory the walk's last step (one read-ahead buffer, not three: earlier releases recover first and hide it) and lower the target from the test vnode while the I/O is out (BufTestVnode's target_at/target_to); `testutil::forbid_sleep(true)` makes a test that must not sleep fail instead of hang (N5.1).
- `vput` expects the vnode locked (its last use calls VOP_INACTIVE, which unlocks it); a vnode fresh from `getnewvnode` is unlocked, so a test or bench releases it with `vrele` (bsd's rrw_exit of a free lock panics, N5.2's bench).
- A test file system that finds its node by a thread-local scan inflates every VOP_LOCK/ISLOCKED in a bench (vop.dispatch 2.8 vs LZ 1.0 ns): benches use their own table over a static lock, as the LZ-shape bench does, so the pair compares the VFS, not the test fs (N5.2).
- The kernel crate cannot move bytes through a `UIO_SYSSPACE` iovec (that is bsd's kcopy): a kernel path that uiomoves into a `Uio<G>` calls a glue leg (`FileGlue::uiomove`); the test glues copy user iovecs through the user-copy double and only account kernel ones (`testutil::test_uiomove`).
- The kernel's mount recycling kpanics on the reuse of a mount freed while busy ("vfs_mount_alloc: reused mount is busy"): a test helper that vfs_mount_free's a mount it never vfs_unbusy'd (udf's, ext2fs's) fails only in the test that allocates again; unbusy first, as sys_mount and the mountroots do (N5.2).
- bsd unit tests that built a detached vnode or mount (`Box::leak(Box::new(Vnode::new()))`) use the kernel's test-only `Vnode::new_unpooled()`/`Mount::new_unpooled(vfc)` (cfg doubles) once the type is the kernel's; the production constructors stay private (N5.2).
- The vnode operations registry (29 slots for file systems' tables, OnceStatic, never reset) is shared by every bsd host test in one process: N5.2 leaves it at about 27 tables (production ones and the tests' DISK_VOPS, TESTFS_VOPS, COUNTING, EMPTY ...); a new test table may hit `more vnode operations tables than 32`: reuse an existing test table first.
- `cargo test -p kernel --features diagnostic`: kernel::fs's bio tests hang and `fs::buf::tests::a_busy_buffer_is_not_acquired_again` overflows its stack (N5.1's, seen 2026-10-29); test a new KASSERT with `-- --skip fs::bio --skip fs::buf`.
- A `kassert!` as a closure's value (`|c| kassert!(..)`, or the tail of a block without `;`) compiles without `diagnostic` and fails with it (the macro's `#[cfg]` statements in an expression position): write it as a statement and build kernel once with `--features diagnostic`.
- A kernel test that reaches `namei` on a test glue without `kernel::fs::testfs` must call `kernel::fs::init::vfsinit::<G>(&[], 64, || {})` first, or `namei` fails with ENOMEM (no namei pool) where the code expects ENOENT (no root).
- Removing a FileGlue fake (advlock log, pathconf 1000+name, isatty, revoked): give the test file a real kernel vnode instead (`testutil::test_vnode::<G>(vtype, flags)`, operations `FileVops` registered with `vops_id`; a revocation is `set_ops_id(VopsId::DEAD)`); a test `Vnops` static must not be a ZST (`_id: u8`), since `vops_id` keys tables by address.
- bsd host tests that open files on tmpfs and call VOP_ADVLOCK or vn_fsizechk need `crate::sys::lockf::lf_init()` and a `Plimit` set on the process (`ps_limit: none` panics otherwise); `tmpfs_vfsops::tests::setup` gives neither.
- `Box::leak(Box::new(Vnode::new_unpooled()))` yields `&mut`: annotate `let vp: &'static Vnode<_> = ...` before `Some(vp)` goes into a `SyncLink::set` (an `Option<&mut T>` does not coerce).
- Spl pairs per op without QEMU: a temporary `splraise` override in kernel testutil's `TestIntr` (a counter, then `hal::intr::dflt_splraise`) and, in a kernel bench's `measure`, the counter's delta over one batch / ops when an env var is set; save and restore both files (never committed). To isolate one function's pairs, add a row of its callee alone (N5.3: `vget.vput.free` beside `cache.lookup.hit`).
- Kernel tests that need a VFS byte path (symlinks' VOP_READLINK into namei's kernel buffer): `testutil::set_copy_kernel(true)` makes the test glues' uiomove copy UIO_SYSSPACE iovecs through hal's kcopy token, taken lazily by the first such call (never in `install`: bsd's test process holds the token for its own uiomove); the test glues' `ni_unveil_match` is a counter (`unveil_final_match`), so a C `= NULL` is observable.
- Two-thread lockf tests: the second host thread needs its own glue tables and curproc (`procinit::<G>`, `process_alloc`, `thread_alloc`, `G::set_curproc`), and "asleep" is read as `ls_pending` under lockf_lock, which the sleeper's `sleep_nsec` releases (bounded 10 s poll).
- kernel::fs::testfs::setup must forget bio's process-wide cache too (`bio_test_reset`): `getnewvnode` raises `maxvnodes` to `bcstats.numbufs`, so a bio test that left 96 buffers made subr's two getnewvnode tests fail whenever they ran next (N5.4, a latent order dependency, not a flake to retry).
- bsd tests whose system call now copies through `hal::user` (N5.4's VFS calls): paths via `vfs_subr::tests::user_str`, a `struct stat` or mount arguments via `user_buf(bytes)` (`UserBuf`, USER_BASE + 0x8000, 12 KiB, one at a time; `UserBuf::stat` decodes `Stat::to_bytes`' layout, `hal::user::bytes_of` encodes an `AbiPod` *Args); export sockaddrs stay host pointers (bsd's own copyin).
- The host user double is one 64 KiB space for every test of a binary (hal/arch/host/copy.rs): grep `USER_BASE + 0x` before picking a range, and hold the MEMORY guard while writing it. Kernel binary at N5.4: event 0x100-0x400, fs::syscalls 0x1200-0x1fff (bio/subr 0x1f00), descrip 0x2000-0x3c00, mmap 0x4000, meter 0x4100, sysctl 0x5000-0x6c00 and 0x9000, getcwd 0x6000, vnops 0x6800, select 0x8000, tty 0xa000, futex 0xd000, log 0xe000, prot 0xf000; sysctl's doproc (0x6000) and proc_args (0x6800) tests take no guard and share getcwd's and vnops's offsets (a latent race, N5.3's). bsd binary: kern_sysctl 0x4000, user_buf 0x8000-0xafff, kern_prot 0xb000, user_str 0xc000-0xffff.
- kernel::fs::testfs::setup's memory has no pages: a test that reaches `getblk` hangs for ever in `buf_get` (waiting for buffer space) and every other test then waits on the MEMORY guard; use `testfs::setup_root_cached(bytes, bufpages)` (N5.5a1 review 1), and check a buffer's release with `incore` before the next `getblk`, so a buffer left busy fails the test instead of blocking it.
- A kernel test path that reaches `sched::r#yield` panics under the VFS fixtures (`with_curproc`: no scheduled thread; testfs's `set_curproc` sets only the glue's): test the decision before the yield as a function of its own (N5.5a1's `unlinked_and_writable`) rather than build a scheduler fixture.
- Run new host tests bounded: `perl bounded.pl SECS cargo test ...` (fork, `setpgrp`, alarm, kill the whole group); a bare `perl -e 'alarm N; exec @ARGV'` kills cargo but leaves the test binary orphaned and the pipe open (N5.5a1 t-a1/bounded.pl).
- A kernel test of a UFS inode's life needs an `InodeOps` double (a static recording its calls) and `InodeInit::ump` (a leaked `Ufsmount`): getinoquota reads `ip.ump()`; test_vnode's usecount 1 keeps `vrecycle` a no-op, and a `vref`'d devvp keeps `vrele` from inactivating it (N5.5a2's ufs_inode tests).
