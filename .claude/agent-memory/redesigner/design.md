- Intrusive links: derive the entry pointer with `NonNull::from(elem).cast::<u8>().map_addr(|a| a.saturating_add(OFFSET))`, never from `&elem.field`, so container_of stays sound (docs/IDIOMS.md typed-handle row).
- Safe readers over intrusive links are sound only if unlink clears the element's links and a poison value is flagged, never followed; tree(3) defines element ops only for linked elements, so clearing is no deviation.
- `crate::crypto::wipe(x)` is `*x = T::default()`, which drops the old value: a `Drop` calling `wipe(self)` recurses; wipe field by field in a `zeroize` (`explicit_bzero` arrays over 32) called by `Drop` and `finalize`.
- A non-Copy key in a `Cell` has no safe by-reference read and `take()`/`set()` exposes the zero key to other CPUs: a shared run-time key is `AtomicSiphashKey` (IDIOMS row); one in a StaticCell is read with `get()`.
- `#[cfg(..)] { value }` as a tail expression is unstable: write `if cfg!(feature = "..") { a } else { b }`.
- `abi_pod!`-style tiling checks (`offset_of!` + sizes) miss unions and omitted zero-sized fields; an exhaustive `let $T { $($f),+ } = *v;` in a never-called closure refuses both.
- OpenBSD opens BOTH pipe files `FREAD | FWRITE` (sys_pipe.c dopipe): which pipe a file holds cannot come from `f_flag`; carry it with the handle.
- `klist_assert_locked` with `kl_ops == None` asserts KERNEL_LOCK under diagnostic + MP: an MPSAFE object cannot use an ops-less klist with the `_locked` forms.
- A `Native` syscall entry must still run bsd's prologue (mi_syscall: refreshcreds, pin_check, pledge_syscall, the kernel-lock rule) on its own sysent row with the syscall number, or the module path silently drops pledge and pinsyscalls.
- bsd's `Klist`/`SigioRef` (anything with `SlistHead`/raw-pointer Cells) are Sync but not Send, so they cannot sit in a `PoolArc` value; the glue holds a leaked, recycled `&'static` (pipe_glue's PipeKlists, IDIOMS row).
- A kernel macro and a fn of the same name in one module clash at `pub(crate) use` (E0255): name the helper differently (`report_unported`).
- A setter taking `&WriteWitness` cannot run while a `Guarded` cell of that lock is open through `get_mut(&mut w)`: counters under a foreign lock are relaxed atomics whose setters `kassert!` the lock.
- A function that makes a value and returns a witness borrowing it takes a `&'v mut Option<T>` slot: `let v: &'v T = slot.insert(t);` returns `(&'v T, Witness<'v>)`.
- Machine lock: release only what you took; take-run-release in a script that releases only after its own `mkdir` succeeded (N3.4c once removed another agent's lock).
- A kernel trait method implemented by bsd over functions taking `&'static Vnode` can declare `fn m(&'static self)` (object-safe for `&'static dyn`).
- An owning container's `remove(&mut self, e: &T)` cannot take an `e` borrowed from it (E0502): give find-and-remove by key (`OwnedTree::take_by`) and validate elements by a container identity in their entry.
- `Guarded::get_mut(&mut w)` borrows the witness for the reference's life: two `&mut` cells of one lock need the witness split into parts (`Divisible::split`); parts borrow the witness, so return a value holding them (`MapSplit`) with `parts(&mut self)` (IDIOMS row). Check a brief's guard signatures against this before freezing an API.
- bsd's `uiomove` over one `UIO_SYSSPACE` iovec is a safe path to `kcopy` (pcb_onfault); making `kcopy` safe would launder legacy blocks and give bsd a safe arbitrary-address write.
- Over an owned intrusive tree, name elements by unique key across inserts, removals and clips (clip_start returns the clip address); a loop that clips its own cursor updates `first` when `key == first`.
- A trait method reading lock-guarded fields without a witness parameter cannot be implemented over `Guarded`: move such reads to the guard trait (`g.aref(e)`).
- `std::panic::catch_unwind(|| f(&x))` stops compiling once `x` gains cells: wrap in `AssertUnwindSafe`.
- Coding against an API another agent writes in parallel: keep its assumed signatures as a never-committed stub file and a script that swaps it out before each commit and back after.
- A mechanical `use` rewrite that splits one `use` into several drops the `#[cfg]` on all but the first: list HEAD's attributed uses and fix those by hand.
- Derived state cached inside `MapState` (Owners, ~180 B) grows `Vmspace` past `the_pool_items_stay_near_the_cs`'s 512 B (vmsppl item size, vmstat -m): compute once per operation and lend `&T` down instead (as fast, no size change).
- A `&'s VmMapEntry` returned from a `&'s mut MapState` keeps the whole state borrowed; inside a loop that reborrows the state NLL refuses it (universal region): return a `Copy` summary, or reborrow with `OwnedTree::insert_get` + destructuring `let MapState { addr, uaddr_exe, .. } = st` for split borrows.
- LZ frees pool items and softcs without dropping them (`proc_free` is a raw `pool_put`; tcpcb, syn cache, sessions likewise): an owning handle (`PoolArc`, `MBox`) inside a legacy struct leaks there; grep the struct's free path before giving it an owning field.
- A task's `pending` kept as its pinned entry's link word (one atomic, cleared by the unlink itself) avoids touching an element after unlinking it, which a separate flag cleared after the unlink would need.
- `PoolArc::from_ref(&T)` needs proof the value is in a pool item (a `PoolHome` field recorded by `get_homed`, `pool_home!`): a bare `&T` may be a `static` (proc0, P4) or a stack value.
- Before planning a type move, check every frozen accessor against its field's lock class: `[o]` handle fields (`p.ucred() -> &Ucred`, `p.vmspace()`) cannot keep a `&` API in a kernel type without a per-thread token (N4.5's `current()`) or an embedded atomic copy.
- zsh: an unquoted `grep --include=*.rs` fails "no matches found" before grep runs; quote the glob (or put the loop in a script file).
- A macro arm `$(impl[..])? $ty:ty` is ambiguous (`impl Trait` is a type): give the generic form its own arm first, keyed on the literal `impl`.
- A kernel type's inherent method shadows a bsd extension trait's method of the same name (Thread::vmspace vs ProcExt::vmspace): keep kernel names off bsd's frozen accessors.
- Once a bsd type becomes an alias of a kernel type, bsd's `impl Proc {}` blocks stop compiling (E0116): move them to the glue's member type, which auto-deref reaches.
- s_count is held by ttys (TIOCSCTTY's sesshold) and tprintf_open too, not only by groups: a counted SessionRef needs holders there.
- An API that removes an element given `&T` cannot be fed a `&T` borrowed from the same guard (E0502): take the element's key (`p_seq`), which the owner reads from itself.
- `if c && let Some(x) = slot.lock().take() { body }` keeps the guard alive through `body` (if-let temporaries): take into a `let` first when `body` may sleep (frele, a close).
- A handle that must take its PoolArc out in `Drop` (`FileRef(Option<PoolArc>)`) loses the null niche: `Option<Handle>` becomes two words and grows every pool item holding one; give nullable holders a one-word slot over the handle's own empty state (kernel::file::FileSlot).
- A per-element Drop on a 20-slot inline table cost ~1 ns a slot in release (fdcopy-20 +37 %); an is_none fast path and a #[cold] close did not move it: measure the table's make+drop row before choosing a Drop.
- A Bash command ending in a stdin reader (`cat > /dev/null`) hangs until the 2-minute timeout and goes to the background: stop it with TaskStop; never leave a stdin consumer in a command.
- A C switch table as a trait (decision 46, N4.4b `Filter<G>`): static methods plus a `const fn of<F: Trait>() -> Table` filling `Some(F::method)` compiles on stable (fn items coerce to fn pointers in const fn), an inline `const { assert!(F::FLAGS ..) }` inside refuses bad flags at compile time, and `&Kqueue::<G>::CONST` of the result is still promoted to `&'static`.
- When an erased table's `None` meant something to the dispatch (the C's NULL: `knote_modify` at splhigh when not MPSAFE, a fault when MPSAFE), make the trait's default method reproduce it by reading `Self::FLAGS`, so `of` can fill every entry and no behaviour moves.
- A field added to a kernel type with the name of a glue member its Deref reaches (`Process::ps_pin` vs `BsdProcessG::ps_pin`) silently shadows it for every bsd caller: grep the glue's member names before adding one, and switch the callers in the same commit (N4.6a's a2 broke bsd's build until a3).
- A safe `get()`/`replace()` pair over an UnsafeCell is unsound safe API; a read-mostly cell needs a reader count (`hal::slot::ReadMostly`), and a reader must not sleep under its guard: allocate first, then copy under a short borrow, again if the size changed.
- A kernel thread creator that must hand bsd its `&'static` (drivers store it) can lend the pinned thread through a callback before it runs (`fork1_with`, `kthread_create_with`): no driver changes, no tid conversion.
- Moving a box into an owner while setting the thread runnable: do `setrunqueue` and the move in one section of the owner's lock (`ps_mtx` before SCHED_LOCK, donice's order), so the thread can run but nothing that needs its box (exit) gets it before the owner has it.
- A waiter on its own stack whose "waiting" flag is a pointer the waker clears and follows (futex's ft_proc): make waiting = its PinEntry being linked and wake the waiter's own sleep channel (its address) under one SCHED_LOCK hold; a move between lists of two locks is PinList::move_where_across, never remove+insert (the waiter would see itself unlinked).
- `&Type::<G>::CONST` is promoted afresh at each site: two promotions of one associated const can have different addresses, so test an erased table (`Filterops`) by its flags and by calling its entries, never `ptr::eq` (N4.7a LogRead).
- A kernel object whose state needs the glue (a `Klist<G>`, a `FileRef<G::FileGlue>`) cannot be a generic `static`: put it in `ProcTables<G>` (`ProcTables::log`); a timeout there is `Timeout::new(f::<G>, null)` in the const fn and `pin_static(&G::tables().x.tick)`; in tests a wheel run on another thread sees that thread's (empty) tables, so its callback must tolerate them.
- hal's `Mutexed<T>` fixes its IPL at construction (`wantipl` is not an atomic): a kernel type holding one is not valid all-zero, so it cannot replace a legacy struct embedded in an M_ZERO softc and initialised later (`bufq_init`'s `mtx_init(IPL_BIO)`): check every embedder before planning such a move (N4.8c stopped there).
- A closed set of per-CPU callbacks (clockintr's five binders) is a slot table inside the queue's `Mutexed` with `Copy` handles (CPU, slot), not PinLists of pinned statics: nothing to pin, no back pointer, the pending order a small array (IDIOMS row).
- A generation-protected record read without a lock (timehands, cq_stat): every field an atomic loaded/stored Relaxed, the C's fences kept; `hal::link::Link` for a swapped `&'static` object (its acquire load costs ~0.4 ns on the reader's path, accepted with the reason).
- A C split lock/unlock pair called from many legacy sites (`sysctl_vslock`/`sysctl_vsunlock`) over a hal witness lock: a guard (`VsLock`: the witness, the kernel lock, what to undo with the saved length) whose `Drop` is the unlock; the legacy wrapper returns the guard and its few callers hold it (no split API needed).
- A registry of per-id `OnceStatic<&'static dyn Trait>` slots refuses at registration the ids the dispatcher never consults, and an unregistered id answers as the C's compiled-out `case` (falls to the C's default path), never a panic.
- A kernel handle to a shared object (a `vmspace` Arc from `vmspace_share` or the PsMtx) is not the C's counted reference: code that pairs it with the C's release (`uvmspace_free`) takes the C's reference first (`uvmspace_addref`), or it drops the owner's count (N4.6b's `ps` purged every address space it listed).
- A host microbench whose op costs ~500 ns is dominated by the clock pair (~45 ns): time a batch (100 ops per pair) before reading a regression; a two-call ONLCR (`putc` twice, two lock pairs) became `Clist::putc2` (one pair) to stay within decision 43's 10 %.
- A legacy `static` sysctl row (kern_sysctl's KERN_VARS) cannot point at a value in the kernel's `ProcTables`: drop the row and serve the MIB in the switch through `sysctl_int_bounded`'s read-only path on a copy, checks in the same order.
- A new hal claim on a page must survive what the C's VM does to every page it maps: uvm_fault_lower ends with clear_bits(PG_BUSY) even on a page it never busied, so an invariant keyed on the PG_BUSY mask (not on the bit being set) panics every process (N4.8a timekeep: a separate PG_HAL_KEEP claim, clear_bits checks the bit is set); write a kernel test that maps, faults, wires and forks the page before claiming it boots.
- A syscall flip whose kernel body needs state still in bsd (N4.8 a6: the itimers, spc_runtime, pledge_adjtime) goes through ProcGlue members, not a bridge: a default for what a test glue can lack, required (no default) for a pledge check; the bsd sysent row stays the prologue and only translates SysArgs.
- A function made generic over the glue is instantiated in its caller's crate: a non-generic, non-`#[inline]` kernel helper on its hot path becomes a cross-crate call there (N5.0's `uvm_map_inentry_recheck`: inentry-hit +12.5 % dev until `#[inline]`).
- Passing the thread (`p: &Thread<G>`) to vm entry points, and `ru: Option<&Rusage>` to the fault and the wirings, replaced a curproc slot without adding G to `FaultMap` (N5.0): pass the record the C bumps, not the thread, where only counters are read.
- A legacy boundary for an object whose ownership moved to a token (N5.1's `sys/sys/buf.rs`): park the token in the object while legacy code holds it by address (`lend` = legacy_ref + park, `token_of` = take the parked one or make a driver's own busy); every legacy fn keeps its LZ name and signature, so 80 importers stay untouched and the unsafe is one site (docs/IDIOMS.md row).
- A caller's walk of another module's locked list with I/O between steps becomes the owner's scan with a pick closure (skip/take/wait), one take per call, the caller restarting from the head as the C does (N5.1 `vnode_dirty_scan`; docs/IDIOMS.md row): no reference into the list and no counted link outlives the lock.
- Never hold a hal::owned counted link (SecondaryRef) across a lock release where the owner may free the element: the owner's take panics on a counted element (I4), so a walk that drops the lock restarts from the head instead of keeping `next` counted.
- hal::owned's checked lists cost about 4 ns per link or unlink on the host (neighbours' owner-id checks, the count's atomic RMW): a 2Q take+release pair 3.8 -> 12.2 ns; an extra count taken only to borrow (BufRef::release's anchor) cost ~4.6 ns per brelse: borrow the token's own hold instead.
- A per-object cell guarded by one static lock, built in a const fn: `Guarded::new_static_mutexed(&CACHE, ..)` keys the cell to the Mutexed, so `st.get(&guard)`/`get_mut(&mut guard)` prove the lock (N5.1's VnodeBufs in every vnode, under the cache's lock).
- No per-object leaf lock taken inside a global lock's sections (N5.1's buffer slot): it doubles the spl transitions of every acquire/release; make the state a `Guarded` cell of the global lock with an atomic state byte for unlocked hints, and give `_locked` variants for callers already holding the guard.
- A legacy by-address boundary over tokens (N5.1 sys/sys/buf.rs): give the busiest calls fast paths that keep the token parked through the kernel's own sections (`brelse_parked`, `biodone_parked`, `bufq_queue_parked`, `bread_parked`/`getblk_parked` parking in getblk's section) instead of take+park around each call; two spl transitions saved per call, measured.
- The C calls pool_get at splbio: hold the cache's mutex across `pool.get(PR_NOWAIT)` first and leave it only when the pool must wait (N5.1 buf_get: one lock section fewer per buffer).
- A bounded table claimed before a call that can sleep and recurse into the same path (bwrite's queue notes across VOP_STRATEGY, vnd's lower writes) must never sleep for a free entry: when full, go on without one and lose only what the entry was for (N5.1's throttle), or it deadlocks.
- A `pool_get(PR_NOWAIT)` tried first to save a lock section counts `pr_nfail` (kern.pool, vmstat -m Fail) every time the pool must grow: a visible counter the C's waiting call never moves; use BoxPool::get_idle (RawPool::get_idle, bsd's pool_get_idle: a free item or nothing, no growth, no count), N5.1.
- biodone of an asynchronous buffer releases it inside its own section (the C's brelse at splbio), and a completion callback that finishes several buffers does them all in one section: each separate lock+brelse is two spl transitions under TCG (N5.1).
- Superseded: the line "The C calls pool_get at splbio: hold the cache's mutex across `pool.get(PR_NOWAIT)` first" is wrong: that try counts pr_nfail whenever the pool must grow; take `BoxPool::get_idle` under the mutex instead and leave it for `get(PR_WAITOK)` only when that answers None (N5.1 second closing review).
- A walk that takes a counted link to the next element must stop at the last one it will process: a link to the element after the run (here any idle buffer past the cluster) held across a release that recovers memory makes the owner's take refuse that element ("still linked from a secondary tree"); compute next only while `i + 1 < n` (N5.1 second closing review).
- bsd's `Cell`-linked heads (`RbtHead`, `TailqHead`, `Cell<Option<&T>>`) can be neither Send nor Sync, so they cannot be fields of a Sync kernel type: one glue member type (`FileGlue::VnodeG`, like `ProcGlue::ProcessG`) takes LZ's `unsafe impl Sync` moved off the old struct (same count, same argument); the kernel type is then Sync but not Send, so its pool is a `BoxPool` + `PoolBox::leak`, not `TypedPool` (which wants `T: Send`) (N5.2).
- A `&'static dyn Trait` table is a fat pointer, so an object's table slot is an id: fixed ids for the kernel's own tables (their `&Type::<G>::CONST` promotions have no stable address) and a registry by data-pointer identity for the legacy statics (non-zero-sized: two ZST statics may share an address) (N5.2 `VopsId`).
- A C wrapper's checks around a dispatched operation (vfs_vops.c: VBIOERROR after fsync, remove's vput/vrele, readdir's ENOTDIR) live once, in the kernel's `vop_*` functions; the legacy `VOP_*` names become thin adapters over them, and the kernel's own callers use the same functions, never `vp.ops().x()` directly (N5.2).
- A token-or-lent enum (`IoBuf { Token(BufRef), Lent(&'static Buf) }`) passes a legacy buffer through a kernel dispatch without a park/take pair (each a cache-lock section, an spl pair under TCG): only the endpoint that needs the token converts (N5.2 strategy/bwrite).
- A legacy `pub static NAME` whose word moved into a kernel tables struct keeps its callers as `pub static NAME: &AtomicI32 = &TABLES.field;` (a reference to another static's field is a valid static initializer; `NAME.load(..)` auto-derefs), N5.2's PRTACTIVE/NUMVNODES/MAXVNODES.
- `pub use` of a kernel generic fn into bsd works where the glue is inferred from a `&Vnode<G>`/`&Mount<G>` argument; where `G` appears only in the return type or behind an unsized coercion (`&'static Vops` to `&'static dyn Vnops<G>`, a `None` mount) write a specialized wrapper (N5.2: getnewvnode, bdevvp, cdevvp, vfinddev, vdevgone, vfs_rootmountalloc, vfs_getvfs).
- A struct a mutex guards whose few words the C's paths read unlocked (mnt_stat's f_iosize in ufs_bmaparray, f_fsid in the NFS attributes): keep those words as Relaxed copies written by the one writer API (`with_stat`) and give them unlocked getters, or every read is a whole copy under the lock and an spl pair the C does not have (N5.2's a30590df).
- A walk that changes an owned tree under it (clips, inserts) holds the C's pointer as a counted link (map.rs `Held` over `SecondaryRef`): its `get()` borrows the hold, not the tree, so it coexists with the state's `&mut`, and `step(&tree)` is RBT_NEXT; release it before the element leaves the tree (I4), and pass `&mut Held` to a clipper that moves it (docs/IDIOMS.md row, N12.1).
- A hold (`SecondaryRef`) must go before the lock or busy mark that keeps its element in the tree: declare it after the guard, or `drop` it before `keep.then_some(g)` (which drops the guard inside the call when false) and before a parameter outlives the guard local; a hold left after the unlock makes a concurrent unmap's take panic (N12.1).
- A function that should return a borrow made in a loop that reborrows `&mut st` each iteration (fix_space's inserts) hits NLL problem case 3; take an out-hold (`&mut Held`) and set it inside instead of returning `&'s T` (N12.1's splitentry and FixFrom::Held).
- Correction to the line on a hold before its lock (N12.1 review): reverse declaration order covers early returns only; an explicit `drop(busy)` or `drop(g)` while a hold is alive (uvm_map_clean's walk ended holding the entry past the range) leaves it counted after the unbusy: scope the walk in a block that ends before the explicit drop of the guard.
- `hal::link::Link<T>` is `Sync` only when `T` is (its `PhantomData<&'static T>`): an atomic word for a bsd `Socket` still needs its container's `unsafe impl Sync`; narrow that impl's text to the `Cell` members, do not add a site.
- A per-table id cache in bsd's `Vops` statics is impractical (17 tables list all 34 slots; a `const` with an atomic trips `declare_interior_mutable_const`) and must be checked per registry anyway: an open-addressed registry keyed by the table's address (Fibonacci home slot, linear probe, set-once slots) gives O(1) with no table edits.
- An immutable field reached through a `ReadMostly` cell (`si_rdev` behind `v_un`) is copied to a plain word on the owner, set before the owner is published and cleared when the cell is emptied; keep a presence bit (bit 32) so an all-ones value (`NODEV`) never reads as absent.
- `TAILQ_FOREACH` reads the next element after the body (a lazy iterator holding the current one), `_FOREACH_SAFE` before it (prefetch): a prefetching walk stops at a successor the body removed, so give each C walk its own iterator.
- A sysctl node of per-glue state is a kernel `XxxNode<G>(PhantomData<fn() -> G>)` with `const NODE`, registered by bsd's kern table (`&XxxNode::<BsdProcGlue>::NODE`, as TtyNode, VfsSysctl, NchstatsNode): the kern registry is one global table, so a generic init (nchinit) registering it would collide across test glues.
- A glue leg that only finds the file's vnode and calls one VOP becomes kernel code over `FileGlue::vnode_of` (N5.3: advlock, pathconf, isatty, position_check, vnode_revoked, getcwd); keep a provided default only where a test double is not a VFS vnode (vnode_ops: MemVnode), and say so in the bridge's comment.
- A safe walk whose body sleeps (vfs_stall's vfs_busy) needs a restart rule for a prefetched successor that was unlisted meanwhile: restart from the head skipping what the pass marked (`mountlist_safe_restart(rev, mask, done)`), never follow a stale link or end early.
- A bsd adapter keeps LZ's helper names for its importers with `pub use kernel::...::{dounmount, getvnode}` (generic over the glue: inference picks it from `&Proc`) and thin wrappers only where the signature differs (`do*at` over a `*const u8` path to `UserPtr`), so no importer changes (N5.4).
- `hal::klock::witness()` raises the IPL to IPL_VM for its life (klock.rs:432-447): a `Guarded::new_kernel` cell changed per operation (an inode's i_flag on every read) costs an spl pair the C lacks; words the C changes under the kernel and vnode locks are relaxed atomics with LZ's get/set (N5.5a1's Inode), only list changes take the witness (N12 row: D-N5.3-2).
- An on-disk structure kept in core and changed member by member: N atomic u64 words with get/set at the POD's `offset_of!` (a CAS per write keeps neighbours) and whole copies through the POD's `abi_pod!` bytes (`DinWords<N>`, N5.5a1): one layout description, the C's item size, no unsafe.
- A bsd glue member holding a `Netexport` (radix nodes with raw-pointer Cells) is not `Send`, so a kernel type carrying it cannot go into `AnyBox`/`ReadMostly`/`TypedPool`: check `Send` of every glue member before planning a typed slot (N5.5a1 left the ufsmount in mnt_data).
- A kernel inode whose identity is plain fields and whose vnode back-link is a `Link`: `ffs_vinit` moves the inode to a device alias (take_node/set_node), so `i_vnode` is not immutable after vget.
- A C object never freed and cached on kernel-lock lists (struct dquot): `MBox::leak` for a true `&'static`, its lists `hal::list::List` (atomic links, no witness): zero spl where a `klock::witness()` would add a pair per section; the generic element needs per-glue adapters through `ufs_glue_links!`/FileGlue associated types (N5.5a2's DqHash/DqFree).
- An owned box the lock holder alone replaces (ip->i_dirhash): `ReadMostly<Option<MBox<T>>>`, read for the whole operation even across sleeps, and dropped before the same thread writes it (`replace` spins on its own reader); the hal rule 'no sleep while reading' exists only for a writer that could spin on the sleeper (IDIOMS row, N5.5a2).
- A C hint read without the lock (dh_next's dh_score, TAILQ_NEXT != NULL, the unlocked dh_hash test): a relaxed word beside the Rwlocked data, written under the lock, or a word holding the list's last element's address; taking the lock instead would add a section the C lacks.
- A PinList element borrowed from `first(&w)` blocks `remove(&mut w, ..)`: take what you need from it in a block (detach its arrays under its own lock), end the borrow, then `remove_first(&mut w)` while the list lock is still held (N5.5a2's recycle).
- A kernel endpoint that needs a block's bytes from an InodeOps::bufatoff that returns IoBuf::Lent pays a take (and a park to give it back to bsd): make the bsd impl return the token (kernel bread + buf_adjcnt on the token) and keep bsd's own callers on the lent path; spl counts stay the base's (N5.5a2's ffs_bufatoff_token).
- A type flip of a C pointer with sentinels (`*const Ucred` with NOCRED/FSCRED) goes cheapest from the roots: make the legacy sentinel consts the new type's (`pub const NOCRED: Cred<'static> = Cred::NOCRED`) and their uses compile unchanged (139 at N5.5a2c); only the pointer's producers and readers need edits.
- A member borrowed for the whole call while the callee takes the owner `&mut` (nfsd's `nd_cr` in every nfsrv_* with `nfsm_*(nfsd, ..)`): move it out at the dispatcher and pass it beside the owner (`mem::replace`, then put back); a copy instead would hide in-place writes the C makes through the alias (nfsrv_fhtovp's anonymous mapping, a security check).
- `&mut` is invariant: a swap of `Cred<'a>` fields between two structs of different lifetimes cannot type-check; if both hold the same value by construction (both lookups' cn_cred are the thread's), swap the rest and kassert the shared one equal (N5.5a2c swap_lookup).
- A struct with one lifetime (`NfsmInfo<'a>`) declared before a loop cannot borrow a per-iteration local: NLL keeps 'a alive to the struct's last use; hold the borrowed owner once before the loop (and say why the C's per-iteration read is matched by an interleaving it allows), or declare the struct inside.
- A third pointer-carrying variant in an enum whose two variants shared a pointer's null niche (KnHook: Timer(PoolArc) | Shared(AnyArc)) needs a tag word: the enum grows by 8 bytes and a pool's pinned item-size test fails (knotepl 296 -> 304 at N5.5a3); count the variants before adding one to a pooled struct's member.
