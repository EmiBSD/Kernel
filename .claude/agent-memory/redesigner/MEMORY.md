# redesigner: lessons across runs

One line per lesson, appended at the end; task state goes in HANDOFF.md
(`.claude/rules/subagents.md`, "Memory"). Committed with the tree.
- The smoke ESP image (`IMAGE_SECTORS`, tools/xtask/src/boot.rs) holds the debug kernel plus the ramdisk; a redesign that lets LLVM inline more grows `.debug_info` by MBs even when `.text` shrinks, and every `--expect-ramdisk` smoke then fails with a bare "xtask: No space left on device". Compare `llvm-objdump -h` of the old and new `bsd` (the sysroot's `lib/rustlib/<host>/bin/`) before blaming the code; N2 raised the image to 256 MiB.
- Worktree sandbox: git commands must be plain (`git show`, `git add <path>`), never `git -C`, never chained with `&&` after other git calls in one line, never with variables; `reference/emibsd-lz` cannot be queried with git from a worktree, so confirm an LZ blob with `diff` against the clone's file and `cargo xtask lz check`.
- clippy `declare_interior_mutable_const` fires on a named `const` of a type with `Cell` links (queue heads) in tests; use an inline `const { .. }` block instead.
- `kassert!` without `diagnostic` still builds a closure per expansion (to keep names used); in generic hot helpers gate it with `#[cfg(feature = "diagnostic")]` and call `crate::kassert!` by path so no import goes unused.
- The host build with `--features diagnostic` was broken at the M16 sync (dev/usb/ucom.rs, `usbd_errstr` not imported); to run a module's diagnostic tests, patch it locally and `git checkout` it before committing.
- Worktree sandbox: run git, cargo and file moves as plain single commands from the worktree root; compound lines (cd+git, loops over cargo, `python3 /dev/stdin`) are refused; write edit scripts to the scratchpad and run them with paths as args.
- Clippy: `cargo clippy -p bsd --all-targets` drags in hundreds of unrelated test-code lints; check as `just clippy` does (lib only, host and `--target ... --features qemu`; `qemu,multiprocessor` before decision 40).
- Intrusive links: keep element-wide provenance by deriving the entry pointer with `NonNull::from(elem).cast::<u8>().map_addr(|a| a.saturating_add(OFFSET))` (safe, stable), never from `&elem.field`, so a container_of step back is sound; became a docs/IDIOMS.md row (typed handle, tree.rs/subr_tree.rs).
- clippy::type_complexity fires on `PhantomData<(&'a X, fn() -> T)>`; split it into two PhantomData fields.
- Safe readers over intrusive links are only sound if the unlink path clears the unlinked element's links and a poison value is flagged (never followed); tree(3)/RBT_INIT(9) define element ops only for linked elements, so clearing is not a deviation.
- `crate::crypto::wipe(x)` is `*x = T::default()`, which drops the old value: a `Drop` that calls `wipe(self)` recurses forever; wipe field by field in a `zeroize` (arrays over 32 elements have no `Default`, so `explicit_bzero` them) and let `Drop` and `finalize` call it (docs/IDIOMS.md, hash-context row).
- Dropping `Copy` from a type breaks `Cell::get` and `StaticCell::read` at the call sites, not only by-value passes: use `take`/`clone`/`set` on the Cell, `get().clone()` on the StaticCell (same unsafe count).
- A compile-time "not Copy" check on stable without a crate: `crate::crypto::testutil::assert_not_copy!` (ambiguous impl, fails with E0283 naming the Copy type).
- Worktree sandbox: `awk` programs, `$((..))` arithmetic and multi-statement heredoc pipelines are refused; put loops in a script file in the scratchpad and run it with paths as arguments.
- `sys/lib/libkern/lib.rs` is a crate root AND an inherited `[[module]]` of lineage.toml (the only tracked one); `lz check` compares modules without `#[forbid(unsafe_code)]` lines on `mod x;` declarations, so the forbid ratchet there keeps it inherited.
- Worktree sandbox: to stage many paths without variables, `git diff --name-only > <scratch>/paths.txt`, then `git add --pathspec-from-file=<scratch>/paths.txt`.
- A file with no `unsafe` token still fails under forbid when it invokes a macro whose body has one (28 such macro_rules in sys/: byte_view!, scsi_wire!, usb_wire!, ...); scan macro bodies with a lexer and grep the invocations before trusting a sweep to the CI configurations alone.
- Filtered `cargo test -p bsd --lib -- <names>` runs mislead: `if_wg::tests::wg_ioctl_dispatch` (panic "no idleproc set on CPU0") and `wg_cookie::tests::cookie_mac_test*` (uptime still 0, so no mac2) fail at the baseline too under a filter; confirm any failure with the full `just test` before blaming a change.
- pf tests under `#[forbid(unsafe_code)]`: keep IPv4 addresses in the descriptor's own header copy (`PfLoc::Hdr(size_of::<Tcphdr>())`, written with `pd.st_addr`, 8 bytes fit in the 28-byte copy) instead of `unsafe { PfLoc::local(ptr) }`.
- A non-Copy key in a `Cell` has no safe by-reference read and `take()`/`set()` exposes the zero key to other CPUs; a shared run-time key is `AtomicSiphashKey` (docs/IDIOMS.md row), and a key in a StaticCell is read with `get()` (a reference) and compiles unchanged.
- Worktree sandbox: a heredoc that writes a Python edit script was refused as "too complex" when its text contained shell-looking words; write such scripts with the Write tool into the scratchpad instead.
- A `[[module.fn]]` row lives only under a module whose `lz` list names the row's LZ file, and adapted modules carry no rows: moving an item out of an adapted module (fp_socket into sys/sys/file.rs) means the redesigned target lists that LZ file, with its licence blocks, `//! Upstream:` and `//! LZ:` lines.
- Before promising "module X becomes forbid", list every `unsafe` in X: header modules hold `unsafe impl AbiPod for <repr(C) struct>` (about 200 tree-wide) and raw-pointer accessor derefs that no slot redesign removes; an AbiPod impl blocks forbid until a core mechanism exists.
- Taking a value out of an `OnceCell` through `&T` at a point of proven exclusivity: `(*ptr::from_ref(&x.cell).cast_mut()).take()` (an OnceCell is all UnsafeCell, so the `&mut` is allowed); never cast the whole struct to `&mut`.
- Edit scripts for many call sites: a Python replacer reading OLD/-----/NEW blocks from a spec file (exact match, once unless `@all`), run as `python3 <script> <file> <spec>`, passes the worktree sandbox where heredoc-python and shell loops do not.
- lineage's exclusion of `sys/stand/` covers the kernel's boot glue only (`sys/stand/mod.rs`, `bootarg.rs`, `limine.rs`): `sys/stand/boot/*.rs` and the efiboot files are `[[module]]`s and turn `adapted` when touched.
- `cargo xtask hal-check` wants `// SAFETY:` on the line right above the one holding `unsafe`: `let x =` on one line and `unsafe { .. }` on the next fails; bind the pointer first, then `let x = unsafe { .. };`.
- `cargo xtask abi-check` scans every `.rs` under `sys/abi/`, build scripts included: a `build.rs` there may not branch on a value (emit its link args unconditionally).
- A `[[module.fn]]` row's bare `native` names resolve only in the row's own module; a target in another module needs `sys/<path>.rs::name` even when that module lists the same LZ file.
- In a `forbid(unsafe_code)` crate `#[unsafe(no_mangle)]`, `export_name` and `link_section` are refused; a separately linked binary's entry can be found by a `#[used]` static whose name a linker-script glob matches (`KEEP(*(.data.rel.ro.*NAME*))`) and `ENTRY(sym)` set on it.
- A `no_std` bin whose graph links `alloc` needs a `#[global_allocator]`; keep the crates a stateless module links (hal, kernel) free of `extern crate alloc`, or give the module an allocator over its vtable.
- Without a build (decision 23), `cargo fmt --all` is the only parser run: it caught `gen` as a field name (reserved in edition 2024); run it after every new file, it fails on any syntax error.
- The pre-commit hook's `cargo fmt --check` resolves every `mod` line, so a `git mv` of a module breaks the commit unless the old `mod` still resolves; the user forbids `#[path]` even transiently (2026-10-16): move into another crate as git mv + re-export shim + mod fix in the same commit.
- `#[cfg(..)] { value }` as a function's tail expression is an attribute on an expression (unstable); write `if cfg!(feature = "..") { a } else { b }`, which also keeps helpers used in every configuration.
- hal can reach panic(9) without naming bsd: `core::panic!` goes to the image's `#[panic_handler]` (bsd's lib.rs calls panic(9) with the message) and unwinds on the host for `#[should_panic]`.
- Moving a legacy module into hal also moves its `pub unsafe fn`s, which rule 0.2 forbids there (the lists and trees had 52; the review made us move them back): before moving anything into hal, `grep -c "pub unsafe fn"` it; hal pieces are written new with a safe API.
- `abi_pod!`-style tiling checks (`offset_of!` + sizes) miss unions and omitted zero-sized fields; an exhaustive destructuring `let $T { $($f),+ } = *v;` in a never-called closure refuses both.
- A guard that saves the old spl must record whether it raised anything: restoring IPL_NONE for a guard taken before the IntrLevel bridge was registered lowers the real level.
- Worktree sandbox: `PATH=...:$PATH cargo ...` is refused; call `/opt/homebrew/opt/rustup/bin/cargo` by absolute path from the worktree root (`cargo fmt --manifest-path <wt>/Cargo.toml -p <crate>`, `cargo xtask lz check`).
- OpenBSD opens BOTH pipe files `FREAD | FWRITE` (sys_pipe.c dopipe): a file reads its own pipe and writes its peer's, so which pipe a file holds can never be derived from `f_flag`; carry it with the handle.
- `klist_assert_locked` with `kl_ops == None` asserts KERNEL_LOCK under `diagnostic` + MP (kern_event.c KLIST_ASSERT_LOCKED): an MPSAFE object (pipe, socket) cannot use an ops-less klist with the `_locked` forms; it needs a lock-kind kern_event knows.
- `unsafe-report` counts `cfg(any(test, feature = "x"))` code as kernel code: exposing hal's `testutil` under a feature would add its `unsafe`; a dependent crate's tests can register safe doubles of hal's bridges themselves (leaked `Box<[Page]>` blocks, `NonNull::from(slice).cast()`), as sys/kernel/testutil.rs does.
- A kqueue filter runs under its object's lock but is called back through `knote_locked`/`knote_process`, where no `Rwlocked` guard can be passed: what filters read must sit outside the lock-owning state, as atomics stored only under the guard (docs/IDIOMS.md row).
- A `Native` syscall entry must still run bsd's system call prologue (mi_syscall: refreshcreds, pin_check, pledge_syscall, the kernel-lock rule), and pin_check/pledge read the number: give the KernelApi slot the syscall number and have bsd's glue run `mi_syscall` on its own sysent row, or the module path silently drops pledge and pinsyscalls.
- bsd's `Klist`/`SigioRef` (and anything with `SlistHead`/raw-pointer Cells) are Sync but not Send, so they cannot sit by value in a `PoolArc` value; without an `unsafe impl Send` the glue holds a leaked, recycled `&'static` of them (pipe_glue's PipeKlists, docs/IDIOMS.md row).
- `cargo xtask gen-syscalls` rewrites init_sysent.rs's `use` lines from where `pub fn sys_*` live, and also writes a stale `sys/sys/syscall.rs` (the header moved to hal): delete that file after running it.
- `unsafe-report --write` sets every `unsafe-budget.toml` row to its current count, so one new `unsafe` in arch code (core rows too) fails `--check`; read the row before promising `Unsafe: x n -> n+1`, design for zero first (owned atomics), and hand the raise to the user.
- amd64: OpenBSD's kernel_map never executes (pmap_alloc_level puts pg_nx on every directory entry); executable kernel pages exist only under the KERNBASE slot's directories. arm64's kernel_map does execute (no PXN, no PXNTable).
- Under Limine the smoke transcript did not show a kprintf made inside pmap_bootstrap (boot(8)'s did); prove early-boot code by an effect printed later (a page walk at module load), not by an early line.
- `cargo xtask lz trace` takes `<lz path>:<item>` with ONE colon (`sys/arch/amd64/amd64/pmap.rs:pmap_bootstrap`); `::` silently reports "not found".
- A subagent's commit that raises an `unsafe-budget.toml` ratchet (hal_ceiling) is refused by the permission classifier: stop, leave the message in the scratchpad, the user makes that commit; the series may go on with `--check` red on that line only.
- lineage treats every `mod.rs` (and all of `sys/hal/arch/host/`, `sys/hal/machine/`) as structural (`is_structural` in tools/xtask/src/main.rs): a hal API that needs a `[[module]]` record is `x.rs`, not `x/mod.rs`.
- `bridges.toml` `paid_by` accepts `N2`..`N9` only (bridges.rs `is_milestone`): a slice (N3.3) goes in the row's comment.
- A hal API whose backends land in later commits: gate `pub mod x` (and its `bridge!` slots, `#[cfg]` on the macro call works) to the targets that have a backend, so both machines build at every commit; `bridge!` takes an optional `#[attr]` after the reader's name for an `allow(dead_code)` until the reader exists.
- `cargo xtask lz check` (the hook) walks every .rs on disk, untracked ones too: to commit a fix in the middle of uncommitted work, save `git diff` as a patch, move the new files out of the tree, `git checkout` the touched files, commit, then `git apply --3way` and move the files back.
- `#[forbid(unsafe_code)]` on a module also refuses an `unsafe fn` declared in it: a wrapper whose soundness needs a caller promise goes in the (non-forbid) module that calls it.
- The arm64 kernel target is `aarch64-unknown-none-softfloat` (justfile `arm64`, rust-toolchain.toml); `cargo check --target aarch64-unknown-none` fails with "can't find crate for core" (not installed), which is not a code error.
- `cargo fmt -p hal` parses the cfg'd-out arch modules too (amd64 and arm64 on the Mac host), so it is the cheap syntax check of backend code the host cannot compile; it does not type-check.
- arm64's `ap_bits_user[PROT_EXEC]` is execute-only (AP 0b10: EL0 fetches, cannot load): a compile-time check "EL0 reads every user leaf" is wrong for it; write the PTE asserts from the C's table, not from intuition.
- `PoolBox`/`SharedBox` are two words (item + pool): a slot that is one word of a page (arm64's vp3 `vp[]`) needs `SharedBox::into_raw`/`from_raw`; a typed slot array would need a third page per table at every level.
- `in` is a keyword: an `asm!` operand named `in = out(reg) _` does not parse; name loop registers `cnt`, `ia`.
- `[[dropped]]` is refused (lz check) for an LZ file still in any module's lz list: an LZ file absorbed by hal modules that list it needs only the `[[module.fn]]` rows for its items no hal item covers by name.
- lz check resolves trait-impl methods as `Type::method` in any file (`sys/arch/amd64/mod.rs::Machine::pmap_activate_md`, `sys/hal/pmap.rs::Pmap::drop`), so rows may target the structural mod.rs and machine adapters.
- When the direct map's base moves into `hal::pmap::bootstrap`, everything that used LZ's early static before bootstrap (amd64 consinit: efifb's early map, the VGA hole) breaks; move the bootstrap before consinit.
- A device softc is zero-initialised by autoconf: a non-pointer handle (`Option<PmapRef>`) cannot live in it; keep it in a module `OnceStatic` and leave the softc's raw pointer for identity.
- bsd host tests get hal's pool backend only from `kernel::testutil::install()` (dev-dependency, once per process, heap-backed): a hal TypedPool used by bsd host code must install it before `init`, never bsd's subr_pool (its memory is renewed per test).
- arm64 hal: `Backend::virtual_space()` sets PMAP_VIRTUAL_SPACE_CALLED (vp tables stop being stolen); bootstrap-time code that needs the managed range must use VM_MIN/MAX_KERNEL_ADDRESS or `stolen_bounds()`, never amd64's `virtual_space()` pattern.
- arm64 layout: the image (kernel.ld 0xffffffff80000000) is L1 slot 510 and kernel_map/vmmap L1 slots 0..3 of the same L0 slot 511; the direct map is L0 slot 0. Grep hal's inherited include/pte.rs before adding a C constant: Lx_PT_PXN was already there though a brief said it was missing.
- A spec-file replacer that splits on "\n=====\n" must rstrip the spec's final newline, or the last block's NEW gains a blank line (cargo fmt removes it, but only after a failing check).
- `lz check` refuses a `redesigned` bsd module outside unsafe-core.toml whose `mod` line is not `#[forbid(unsafe_code)]`: a bsd header split into the kernel crate that keeps `unsafe` behind (uvm_extern's Vmspace) is `adapted` with `adapted_by` the kernel modules; a 0-unsafe adapter gets the forbid on its `mod` line and is `redesigned`.
- bsd's host tests run on the kernel crate's doubles (`kernel::testutil::install` from the host's lazy pmap bootstrap), so a kernel bridge's test doubles get their own installer (km_install) or bsd's real implementations are refused; and a bsd static that takes a kernel provider needs a `#[cfg(test)]` const for the double where the host (PMAP_NOMMU) refuses the real one (pipe_glue's PIPE_PAGES).
- clippy `too_many_arguments` counts `&self` on a trait method declaration (7 max); impls are not linted, so one `#[allow(.., reason)]` on the declaration covers them.
- `python3 - <<'EOF' ... EOF` edit scripts (exact-match replace with an assert on the count) passed the worktree sandbox all through N3.2; a `sleep N; ...` chain and `$((..))` in a Monitor command were refused: put the watcher loop in a script file and run it with the log as argument.
- `core::arch::x86_64::__cpuid` is a safe fn on the pinned 1.98.1: hal can read CPUID (amd64 non-MP `ci_cflushsz`) with no new `unsafe` and no bridge; bsd's `#[allow(unused_unsafe)]` around `__cpuid_count` is a leftover.
- A redesigned module whose `lz` list mixes a source with no licence text (`license = "none"`, cpuswitch.S) and a licensed one must drop `license = "none"`: lz check's AuthorOnly policy refuses the second block; say it in the module's `notes`.
- `cargo xtask lz trace` lowercases its whole answer line (`EFI_SPACE_BITS` prints as `efi_space_bits`) and does not see fns declared in `extern` blocks (cpu_switchto_asm: "not found"); neither is a missing row.
- hal::module::load's `LOADING` once-guard is process-wide and taken by one test: test the loader's later steps through `place_and_map`, never a second `load_with`.
- arm64: at pmap_bootstrap TTBR0 holds only bsd's 1 GiB device map (PXN) on both boot paths, so there is no executable identity map; a TTBR1 switch that changes the block size of live global entries (boot(8)'s 2 MiB image blocks to pages) needs break-before-make, which the C and Linux get by running the switch at its physical address: check granularity before promising an in-place switch.
- arm64: the Rust kernel has no BTI landing pads (stable rustc cannot emit them), so kernel text leaves must not carry ATTR_GP on FEAT_BTI hardware (QEMU's cortex-a72 ignores the bit, so no smoke catches it); the kernel pmap's pm_guarded = ATTR_GP still reaches the module window's leaves.
- A global_asm! routine's address with one unsafe site: declare its instruction words as a `safe static` with #[link_name] in an `unsafe extern` block and take `ptr::addr_of!`; the routine section is caught by kernel.ld's `.text.*`.
- Limine 12.9.3 (brew) writes TCR_EL1 = T0SZ/T1SZ | 0xb5003500 | IPS<<32 | DS: no HPD0/HPD1, AS and A1 clear; found by llvm-objdump -d of BOOTAA64.EFI (msr TCR_EL1 then trace x4), a cheap way to answer 'what does Limine leave in register X'.
- To host-test hal arm64 code that needs the inherited include/pte.rs (it names crate::arch::arm64::include::param), sys/hal/arch/mod.rs aliases crate::arch::arm64::include to host's header copies under cfg(all(test, not(target_os = "none"))); pte.rs stays inherited.
- Anything that runs before kmeminit (uvm_init: pmap_init sits between uvm_km_init and kmeminit) cannot use the Rust global allocator: a Box there panics "memory allocation of N bytes failed". hal pools made in pmap_init get their struct pool from BsdPools' STATIC_POOLS (sys/kern/hal_bridges.rs); count them before adding another early pool.
- A pmap window computed from loader input must be checked for non-emptiness at bootstrap: amd64's kernel window under Limine depends on QEMU's memory map (HHDM to ~1 TiB puts it in slot 258); test the pure arithmetic with layout.rs's kernel_window table, including the 1 TiB case.
- MP host tests (`--features multiprocessor`) share CPU 0's per-CPU page magazines across setup_real_memory; uvm_page_test_reset now calls uvm_pmr_cache_test_reset. A new per-CPU cache of kernel memory needs the same.
- Worktree sandbox: `just <recipe>` runs as is (cargo is on PATH); a `PATH=...:$PATH just ...` prefix is refused as too complex.
- `hal::pmap::bootstrap` runs once per test process: every test module of a crate must share one bootstrap (hal `testutil::pmap_boot`, kernel `testutil::pmap_boot` over `PHYS_PAGES`), with a provider whose `page_init_done` is false if any test steals memory (`hal::bootmem`).
- hal `List`/`Tree` elements stay `linked` until removed: a stack `Pglist` must be drained (`pop_head`) before it goes out of scope, and an object's tree emptied by removal (`uvm_obj_free_pages`), or the next insert of those pages panics; there is no TAILQ_INIT/RBT_INIT over a non-empty head.
- Kernel tests over the real page system hold `kernel::testutil::MEMORY`; under `multiprocessor` the per-CPU magazines absorb frees, so count `uvmexp.free + percpucaches`, not `free` alone.
- lz check accepts a `pub use` re-export in an adapted module as the presence of an LZ item that moved (UVMEXP, UvmObjtree, uvm_pagecmp): no `[[module.fn]]` row is needed for those.
- The scratchpad replacer's `@all` block matches substrings: an 8-space pattern also hits the 12-space copy, and a later block for the deeper copy then fails (rep.py exits before writing, so nothing half-applies).
- Editing a TOML row out with a regex like `[^\[]*` stops at the `[` of `for = [..]` and leaves a broken line; remove rows by exact text (the replacer) and run `lz check` (which parses bridges.toml) after.
- The OLD/NEW spec replacer: a spec file's final newline becomes part of the last block's NEW, so an OLD that ends mid-line (or a NEW with a trailing line) splits a doc comment or adds a blank line; strip the spec's final newline in the script and grep the diff for `^+$` and `^ [A-Za-z]` lines before committing.
- Worktree sandbox: a Bash `sed`/`cat` of `reference/emibsd-lz/...` through the worktree's symlink was refused mid-run; never route around a refusal (subagents.md): report it in the hand-back and ask the launching session for the excerpt.
- A kernel crate macro and a fn of the same name in one module (`unported!` + `pub fn unported`) clash at `pub(crate) use` (E0255): name the helper differently (`report_unported`).
- A `uvm_wait`-style "printed once" stub that both bsd and kernel call keeps LZ's once-per-boot output only with ONE site: put the site in the kernel and make bsd's function delegate (the bsd module then turns adapted).
- `amap_lookup` panics on an entry without an amap; any new caller on the unwire/wire path must test `entry.aref.amap().is_some()` first (shared file and aobj mappings have none); a host test maps a `uao_create` object shared with `uvm_map` to get one.
- Since decision 40 (2026-10-17) `multiprocessor` is a default feature of bsd only (hal and kernel have no such option) and bsd's lib.rs refuses a build without it: recipes and checks say `--features qemu`, never `qemu,multiprocessor`.
- An inherited bsd file outside unsafe-core.toml that holds `unsafe` cannot take even a one-line fix: `lz check` wants `redesigned` modules forbid there, and `adapted` needs a redesigned module that forced the change; an LZ bug like ucom.rs's missing `usbd_errstr` import is the user's call (stop and ask; ucom.rs waits for N7, the user's answer of 2026-10-17).
- To measure a baseline (test counts, unsafe-report) inside the worktree: commit, `git checkout -q <base>` (plain, alone), run, `git checkout -q <branch>`; edit nothing in between.
- hal's `pmap` module is `#[forbid(unsafe_code)]` (on its `mod` line in hal's lib.rs): a pmap-shaped piece with `unsafe` goes in a file of its own (`sys/hal/mapped.rs`, an `[[extra]]`) with an inherent `impl KernelMapper` there; check the `mod` line's attributes before promising "in pmap.rs".
- `PoolArc::get_mut` (count 1) is unsound beside `PoolArc::from_value`, which rebuilds a handle from a recorded address at any count: the pools records reach are `TypedPool::init_recorded` (the pmaps), `get_mut` answers `None` there and `from_value` refuses other pools.
- A sealed trait in hal (`Witness`): an inline `mod sealed { pub trait Sealed {} }` in CODE passes `lz check` (only `mod tests` is policed); a fake impl of an unsealed witness trait would forge a lock.
- A cell keyed to a lock that a `const`/`static` must build (`Guarded::new_static`) cannot store the address as `usize` (ptr-to-int is not const): key it `enum { Static(&'static RawRwlock), Addr(usize) }`, both auto `Send + Sync`, no extra `unsafe impl`.
- hal's malloc double refused `malloc(0)`, which `mallocarray(0, ..)` asks for (tmpfs's `uao_create(0)`): the doubles now serve it; kernel::testutil had no Malloc double until N3.4a.
- An OLD/-----/NEW replacer that splits a spec file on `\n=====\n` must drop the file's final newline, or the last block's NEW gains a blank line (a blank between a doc comment and its fn is `clippy::empty_line_after_doc_comments`; one after a Markdown table row splits the table): grep the diff for `^+$` before committing.
- A safe byte view over a frame (`MappedBytes`) needs more than a managed-page check: a per-frame claim bit that only hal sets (`PageMd`'s `PG_HAL_VIEW`) stops two views, a capability (`KernelMapper`) narrows who can build one, and "not a frame that backs kernel memory" stays the token holder's contract until the pages are typed (N3.5): say so, never "as KmBuf's".
- Owned chain cursor: `loop { match cur { Some(c) if c.k != k => cur = &mut c.next, _ => break } }` then using `cur` is refused (NLL case 3); find the position with a shared walk, then step `at` times with an unguarded `match cur { Some(c) => cur = &mut c.next, None => break }` (amap.rs `chain_position`/`chain_at`).
- Before planning a flip of an owner type to witness locking (`Guarded`, `SharedRwlock`), grep its callers for locks taken in one function and released in another (`uvm_fault.rs`: amap_lock in uvm_fault_check, uvmfault_unlockall on ~15 paths, rw_status mode checks): those callers need their lock protocol redesigned, not call-site changes.
- A setter that takes `&WriteWitness` cannot be called while a `Guarded` cell of the same lock is open through `get_mut(&mut w)`; counters under a foreign lock are relaxed atomics whose setters `kassert!` the lock status instead.
- Kernel host tests: `testutil::pages_install(64 * 4096)` left `uvm_pagealloc` answering `None`; 256 pages work. `uvm_page_unbusy` asserts `!PG_FAKE` under `diagnostic`: a test clears `PG_FAKE` (the I/O) before unbusying a fresh page.
- `SharedRwlock` is 16 bytes (two pointer arms, no niche), so a pool item that clones one grows by 16 over a raw lock pointer; check `size_of` before quoting a `vmstat -m` size.
