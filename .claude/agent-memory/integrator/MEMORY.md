# integrator: lessons across runs

One line per lesson, appended at the end; task state goes in HANDOFF.md
(`.claude/rules/subagents.md`, "Memory"). Committed with the tree.
- LZ sync, parallel LZ branches (M16c drivers): each apply conflicts where LZ's merge joined them (pcidevs.rs, mii/miidevs.rs, the ic/pci/mii mod.rs, amd64 ioconf numbering, the smokes list); resolve every one to `git show <merge>:<path>` (ioconf: cfdata renumbered, PV_MII, NCFDATA, MP cpu* as LZ's merge), and record that merge `applied` with `modules` = the shared [[module]]s, or `lz check` compares them with a parent and fails.
- LZ sync: the auto-merge of two LZ branches' pcidevs.rs additions declared PCI_VENDOR_COMPEX twice (ne and dc); take LZ's merge version of shared id tables instead of trusting a clean auto-merge.
- LZ sync: a record's `modules` takes only lineage [[module]] paths (`lz drift` rejects mod.rs, sys/machine/*, and [[extra]]s such as sys/arch/*/conf/ioconf.rs), even when drift.txt lists them.
- LZ sync: tools/xtask/src/main.rs, diffopenbsd.rs and .claude/rules/xtask.md conflict on most xtask commits (native has `lz` where LZ has `ports`); keep ours and insert LZ's new option text by hand, checking against `git show lz/main:<path>` when two LZ branches touched it.
- Never `git commit --amend -F msg` after a message builder that can fail: a stale message file once retitled the wrong commit; have the builder delete the old file first and chain build && commit.
- LZ sync: before cherry-picking, scan every file a chunk brings for LZ items native renamed/split/dropped ([[module.fn]] rows); M16d's rnd.rs (3feb0258) calls the C-shaped chacha_private/sha2 API N1 redesigned, so it cannot equal LZ (security area: stop and hand back).
- LZ sync: when LZ's merge M joins commit K of one branch but also carries later commits of K's branch, K's shared files (ioconf, smokes list) are M less those later commits' own hunks (60214109 = 486e0e43 less cf384384), then M's version at the later commit.
- LZ sync: run the amend of an apply alone, never beside the next cherry-pick; a subject over 72 chars fails the amend and leaves the pick on an unreworded commit (cherry-pick --abort, amend, redo).
- Worktree guard: no shell variables or loops around git/python commands and no heredoc text naming git; write scripts with Write and call them by literal path. /usr/bin/python3 is 3.9 (no tomllib): use Homebrew's python3.13 for the TOML helpers.
- LZ sync, adapted module (rnd.rs over N1's crypto): LZ's tests that `assert_eq!` a redesigned type fail when native dropped PartialEq (ChachaCtx wipes on drop); compare its public field, the one the derive compared, and name each such test line in the commit body.
- LZ sync: after hand-adapting call sites, run `just fmt` before the amend; deleting lines can leave a blank line rustfmt rejects, and once records name the apply's hash the fix becomes a follow-up commit.
- LZ sync: a scripted "ours + theirs" resolution (by LZ merge context) is wrong when both sides end with the same lines outside the conflict (two reference-backed tests in pcidevs.rs): it dropped the first test's closing; build after every scripted resolution.
- LZ sync: when LZ's resolving merge also carries another chunk's branch (475b49bb = M16a + M16d), check the resolution with `git merge-file` (worktree, LZ@other's base, LZ@other) against LZ@merge; a shared inherited table then equals no LZ commit and `lz check` reports it until the integration records that merge.
- Host python3 here is 3.9 (no tomllib); run TOML helpers with python3.13. The worktree sandbox refuses git in a command with variables, $(...) or heredocs: keep git calls literal, or inside a helper script.
- LZ sync: a scripted reword rebase of an unpublished chunk branch renames every commit after the first reworded one; point the record commit's `emibsd` values at the new hashes in the same rebase (an `exec` after its pick that edits lz-sync.toml and amends), or they dangle once the agent's branch is deleted.
- LZ sync, two chunk branches LZ joined in merges M1 then M2: resolve every shared file to LZ@M2 (ident lines stripped), confirm the merged tree differs from LZ@M2 only where a chunk tip differed from its own LZ end, then record M1 and M2 `applied` naming the modules whose content LZ first has at each merge (`lz check` lists them).
- Parallel redesigns of sibling modules (N2: queue.rs and tree.rs) each add the same idiom rows to docs/IDIOMS.md (typed link, panic seam); resolve to one row per idiom naming both modules' functions, scope each claim to the module that has it (tree.rs clears a removed element's links, queue.rs does not), and drop the Candidates entry both rows settle.
- Worktree guard also refuses `$((..))` arithmetic and a `PATH=.. cmd` prefix in a bash line; time a just run and append rc= from a run.sh in the scratchpad, called by literal path.
- Ratchet commit: `unsafe-report --write` lowers `hal_ceiling` to its kernel-code count (35 at N2) while `hal-check` compares its own site count (41) with the same key and goes red; run `hal-check` after `--write`, keep the line and ask (N2 close).
- A generated file moved by a `lineage:` commit (sys/sys/syscall.rs -> sys/hal/sys/) leaves its generator's path behind: `gen-syscalls --check` (in `just check`) then reads "" and reports it stale; grep tools/xtask for the old path after any header move.
- Compile-and-fix pass: run each clippy line of the justfile on its own (a script looping over them), since `just clippy` stops at the first crate and hides the rest; at N2 every line but one was green.
- A red smoke run: group `panic:` lines over target/smoke/*/log before reading recipes one by one; at the N2 close one amd64 panic explained 78 failures, and smoke-tpm passed with it in its log (its expectations end earlier).
- Symbolize a smoke's panic backtrace on this Mac with ~/.swiftly/bin/llvm-symbolizer --obj=target/<triple>/debug/bsd -f -C -i <addrs>; llvm-nm and llvm-objdump are in the toolchain's lib/rustlib/aarch64-apple-darwin/bin/ (a panic_const_* caller pins the exact line).
- First boot of a milestone written unbuilt (N3 close): read one failing log per loader per arch (Limine, boot(8)) before naming a cause; 78 amd64 Limine panics hid a second panic that every boot(8) and arm64 log showed (pool_init through the malloc-backed bridge before kmeminit).
- Worktree guard: it also refuses a python heredoc carrying long replacement text and a `git commit` run through a wrapper script (run.sh); make edits with Edit and run `git commit -F msg` plainly from the worktree.
- bench (N3 baseline): the same kernel differed 15 % in `pipe` between a trial session and the baseline session while each session's own spread was 4 %; `bench compare` compares within-report spreads only, so read a lone `Bench:` line against a second run.
- bench: in the second N3 baseline the first EmiBSD amd64 boot, started the moment `just userland` ended in the same script, recorded every measurement 1.5-3.5x slower than its own warm-up pass and the later runs (no console difference); run `just userland` as a separate step, well before `just bench`.
- bench (N3, ten-run baseline): EmiBSD amd64 `pipe` and `fileread` ran at a slow level in the first three boots of both the 580cd038 and fc622fed runs and a fast one after, OpenBSD alternating with them did not; with the max-min spread that split, not one outlier, is what refuses them.
- A flip that deletes LZ-derived modules (N3.1's pmap, N3.5's sys/uvm/) leaves `applied` records of lz-sync.toml naming them, and `lz drift --strict` fails late in `ci` after every smoke: grep the records' `modules` for paths gone from lineage.toml before the run and point each at the module that took that hunk (27432aa6, 614d65af).
- Never `cp -Rc` target/comp by hand: its .cmd/.d records hold absolute paths, and a run on the stale copy relinked the main checkout's llvm-tblgen; let `just comp` seed it (seed_from_main clones and rebases), then rebase the `*/emibsd-install/*.manifest` files it misses (6 at N3) or the sysroot guard refuses libcxx's includes.
- Host-test flake `dev::ic::pckbc` null deref at kern_timeout.rs:291 (circq_insert_tail): pckbc's test controller() takes kern_timeout::tests::LOCK but never calls timeout_startup(), so it fails when it wins the lock before hidkbd's or kern_timeout's tests; both files inherited, the fix is the user's; one ci rerun.
