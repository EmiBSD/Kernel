# debugger: lessons across runs

One line per lesson, appended at the end; task state goes in HANDOFF.md
(`.claude/rules/subagents.md`, "Memory"). Committed with the tree.
- amd64 kernel_map is NX at the directory level (pmap_alloc_level sets pg_nx on L4/L3/L2, as pmap.c:3041): a leaf entered R|X there still faults with code 0x11; arm64 sets no table PXN, so the same code runs there. Check the whole walk, not only the leaf.
- Page-walk trick: a temporary kprintf of each level's entry via pmap_find_pte_direct's loop (amd64 pmap) settles NX/present questions in one boot; revert it after.
- A smoke whose `--screenshot-after` line comes right before a panic fails with `monitor.sock: No such file or directory` (QEMU exited and removed its socket before xtask's 100 ms poll) and prints no transcript: suspect a crash, not the socket.
- Host profiling on the Mac without root: `xctrace record --template 'Time Profiler' --launch -- BIN`, `xctrace export --xpath '.../table[@schema="time-profile"]'`, then `atos -o BIN -l <load-addr> -i` per frame expands inlined frames (run `dsymutil` on a dev binary first or atos gives no lines); `sample <pid>` is function-level only. Rust v0 symbols need a demangler (no rustfilt; legacy mangling is gone from stable).
- Re-analysing a profile after `cargo build` changed the binary resolves garbage: atos maps addresses against the current file; record and analyse against the same build.
- bsd's legacy host tests ran VMMAP_DEBUG tree sanity on every map lock and uvm_pmr_assertvalid under cfg(test): time LZ-era uvm only with those cfgs turned back to their features. kernel::testutil's pool/malloc doubles leak a zeroed 4 KiB block per item: a timing loop needs recycling doubles registered first.
- N3 perf (decision 42): fork/exec/map cost is dominated by map.rs re-finding entries by key (`ent(&st.addr, key)`, ~12-15 tree searches per cloned entry) with hal::owned's per-node ownership check, plus MapState::owners() rebuilt per call; host fork70 8.4 -> 19.5 us vs LZ at 20035fd0.
- A number passed as a thread's `*mut c_void` argument through bsd's fork1/kthread_create must never be 0: fork1 does the C's `arg ? arg : p`, so 0 arrives as the new Proc's address (N4.5a idle thread of CPU 0, fixed by idle_arg = n + 1, like kernel::thread's tickets).
- A Rust index-out-of-bounds near 2^59 (0x07ff_fffc_...) is a kernel heap address 0xffffff80... divided by 32 (a bit-set word index, `n / 32`): multiply back to find which pointer was used as a number.
- smoke-efiboot in a fresh worktree fails at `efiboot-disk --arch amd64` (not skipped by decision 44) for want of BOOTX64.EFI and the x86_64 bsd: `cp -c` main's stale copies of both into the worktree's target (nothing amd64 is built or booted).
- The worktree guard refuses `$(...)` arithmetic, `S=...; cmd $S`, `git -C` and any Bash text naming the reference trees beside a write: timed smoke loops go in a scratchpad script run with `bash <script>`; the reference symlinks are made from the worktree root with a relative link name; memory lines that name those trees are added with Edit.
- A `has no entry for address` panic in kernel::vm::map (entry_at) means the map's tree is empty or broken, not a bad address: a temporary dump of `tree.iter()` and min/max in that kpanic settles it in one boot (smoke-diag 2026-10-23: empty tree = the vmspace purged under a live process).
- Since N4.2 a VmspaceRef/`vmspace_share()` handle is NOT a vm_refcnt reference (PoolArc keeps the item only): every `uvmspace_free` must pair with a `uvmspace_addref`/`uvmspace_share`; a missing addref silently purges a live address space (fill_kproc made `ps` empty every process).
- Bisecting a smoke over main: `git checkout --detach <merge>` in the worktree + `just <smoke>` under the lock is ~1 min per step on arm64 (incremental build); first-parent merges only.
- smoke-diag `sleep 5 & kill -TERM $!; wait $!` can print rc=0 (~1 in 10 at -smp 2, 2026-10-23): the SIGTERM lands in the forked ksh child before its exec, its inherited trapsig catches it and cleartraps forgets it (bin/ksh jobs.c exchild, trap.c); a race of the command, not the kernel.
